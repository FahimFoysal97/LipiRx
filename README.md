**LipiRx** is a modern Kotlin Multiplatform (KMP) and Compose Multiplatform mobile application designed for retail pharmacies in Bangladesh. It leverages a **Supervisor-Driven Multi-Agent AI System** built with **JetBrains Koog Architecture** to scan handwritten doctor prescriptions and automatically extract, normalize, enrich, and safety-audit medicine brand names, generic compositions, dosage schedules, and calculated quantities.

It features a **Multi-Provider AI Architecture** supporting **Google Gemini**, **OpenAI**, **Anthropic Claude**, **Groq**, **Custom OpenAI-Compatible Endpoints** (such as local Ollama or private LLM proxies), **Edge On-Device SLM (LiteRT-LM)**, an **Embedded Model Context Protocol (MCP) Server**, and an **Automated Evaluation & Regression Testing Harness (`RxAgentEvaluator`)** for seamless integration with external AI tools and desktop pharmacy POS systems.

## ✨ Core Features

1. **Supervisor-Driven Multi-Agent Orchestration (JetBrains Koog)**:
    - Configurable **Per-Agent AI Assignments Matrix** allowing developers and pharmacists to assign specific primary providers/models AND dedicated fallback providers/models for every agent (including `📱 On-Device SLM`).
    - Single-expanded **accordion card behavior** in Settings preventing visual clutter.
    - Dynamic 5-stage analysis UI (`LoadingView`) showing live Supervisor reasoning (`decision.reasoning`), per-agent task completion percentages (`0% → 100%`), active agent name banners, animated feed card expansion (`animateContentSize`), and execution timing logs.
    - **Explicit "View Results" Completion UX**: Replaced automatic completion transitions with an explicit "View Results" primary action on `LoadingView`, allowing pharmacists and developers to inspect the full multi-agent progress and reasoning feed prior to navigating to results.

2. **Self-Healing & 3-Attempt Retry Execution Wrappers**:
    - **Cloud AI 3-Attempt Retry Rule**: `CompositeAiService` attempts primary Cloud AI model requests up to 3 times before triggering the agent's assigned fallback model.
    - **JSON Self-Healing Wrapper (`SelfHealingAgentExecutor`)**: Automatically catches `SerializationException` and JSON formatting errors, generates targeted schema repair prompts, and retries execution up to 2 times.

3. **Jetpack Navigation 3 Architecture & Feature ViewModels**:
    - **Navigation 3 Destination Architecture**: Type-safe destination state management via `AppNavKey` and `AppNavigator`. Back-stack state survives Android screen rotations and configuration changes using Compose `rememberSaveable` with a custom `Saver`.
    - **Dedicated Feature ViewModels & Koin DI**: Testable, feature-aligned ViewModels (`HomeViewModel`, `ImagePreviewViewModel`, `AnalysisLoadingViewModel`, `ScanResultsViewModel`, `HistoryViewModel`, `SettingsViewModel`), bound in Koin dependency injection modules and isolated within modular package hierarchies (`presentation/home`, `preview`, `loading`, `results`, `history`, `settings`, `common`).
    - **60/120 FPS Smooth Theme Transition Engine**: Single-driver linear color interpolation (`LipiColors.lerp`) in `LipiRxTheme`, animating all 22 custom design tokens and Material 3 color schemes seamlessly without recomposition lag.
    - **3-Way Animated Theme Switcher**: 3-segment theme control in Settings featuring a spring-physics sliding highlight pill (`animateDpAsState` + `spring`) and smooth text/icon color transitions.

4. **Per-Scan Accordion AgentOps Telemetry Dashboard**:
    - Grouped raw execution traces into **Per-Scan Session Accordion Cards** (`TelemetryScanSession`), displaying pipeline duration (formatted in hours, minutes, seconds, and milliseconds via localized string resources), total hops, extracted item count, pass/fail status, and AI Engine summary (`Gemini • gemini-2.5-flash` or `Multi-Provider (Gemini, OpenAI)`).
    - **Individual Session Trace Deletion**: Delete single scan trace sessions or clear all telemetry records with confirmation dialogs.
    - Single-card accordion expansion behavior revealing detailed in-card per-turn agent reasoning and diagnostics.
    - Permanent **"Run Benchmark"** action bar with updated action icons (`PlayArrow`) in the telemetry header for instant evaluation triggers.

5. **Embedded Model Context Protocol (MCP) & OS Integration**:
    - JSON-RPC 2.0 server (`LipiRxMcpServer`) and local HTTP listener (`McpHttpServer` on port `8080`).
    - Exposes Room 3 KMP prescription history (`lipirx://history/scans`), provider configurations (`lipirx://config/providers`), and SQLite AgentOps forensic traces (`lipirx://history/traces`) as MCP Resources.
    - Exposes `RxAgentTools` (Vision OCR, entity parsing, generic substitutes, patient safety audit, `get_agent_execution_traces`, and `eval_run_benchmark`) as executable MCP Tools for terminal scripts, Claude Desktop, Cursor, and POS desktop software.

    - SQLite table (`AgentExecutionTrace`) automatically recording every supervisor turn and worker tool execution with timestamps, provider/model metadata, reasoning steps, feedback prompts, execution durations, item counts, and error status.
    - `LipiRxLocalDatabase` guarantees all tables exist on initialization (`init { ensureTablesExist() }`) with automatic fallback retry handling.

7. **Automated Multi-Agent Evaluation & Regression Testing Harness**:
    - `RxAgentEvaluator` executes the pipeline against golden benchmark test cases (`RxEvalTestCase`), computing extraction accuracy %, turn counts, and latency.
    - Exposes on-device evaluation runner via MCP Tool `eval_run_benchmark` (`http://localhost:8080/lipirx/mcp`).

## 🤖 Multi-Agent Architecture

Unlike fixed single-prompt systems, LipiRx uses an autonomous **Manager/Supervisor Multi-Agent Pipeline** powered by `KoogRxSupervisorEngine` where a master LLM agent dynamically evaluates workspace state, dispatches tasks to specialized `RxAgentTools`, passes feedback prompts, and controls pipeline execution.

```
                      ┌─────────────────────────────────┐
                      │        RxSupervisorAgent        │
                      │    (Manager / Supervisor LLM)   │
                      └────────────────┬────────────────┘
                                       │
            Evaluates SupervisorState via KoogRxSupervisorEngine
     & dynamically decides: Next Tool, Reasoning, and Feedback Prompt
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
 [executeVisionOCR]           [executeEntityParsing]       [executeSafetyAudit]
```

### 1. Supervisor Manager Agent (`RxSupervisorAgent` & `KoogRxSupervisorEngine`)
- **Role**: Evaluates the workspace state (`SupervisorState`) on each turn.
- **Dynamic Decision Loop**: Prompts the assigned Manager LLM (e.g. Gemini 2.5 Flash / GPT-4o / Claude 3.5 Sonnet) to decide which agent tool executes next (`TRANSCRIPTION`, `ENTITY_PARSER`, `GENERIC_SUBSTITUTE`, `SAFETY_AUDITOR`, or `FINISH`), generating detailed reasoning and custom `feedbackPrompt` instructions.
- **Rule Fallback & Guardrails**: Includes robust decision fallbacks and guardrails preventing premature finishing when workspace items are empty.

### 2. Type-Safe Koog Agent Tools (`RxAgentTools`)
1. **`executeVisionOCR` (Stage 1)**: Encodes images to Base64 and executes Multimodal Vision OCR to extract raw handwriting.
2. **`executeEntityParsing` (Stage 2)**: Parses and normalizes medicine forms, strengths, units, schedules, and total unit calculations using structured `ParsedEntityDto` JSON.
3. **`executeGenericSubstituteSearch` (Stage 3)**: Cross-references DGDA active ingredients and matches 3–5 Bangladeshi brand substitutes (with manufacturer names) using `GenericSubstituteDto` JSON.
4. **`executeSafetyAudit` (Stage 4)**: Audits dosage safety, interaction risks, unreadable spellings, and sets pharmacist review flags using `SafetyAuditDto` JSON.
5. **`get_agent_execution_traces` (Stage 5)**: Queries local SQLite AgentOps execution traces for forensic auditing and performance telemetry.
6. **`eval_run_benchmark` (Stage 6)**: Runs automated multi-agent accuracy & regression test suite on-device and returns JSON summary report.

## 🔌 Model Context Protocol (MCP) & OS-Level Integration

LipiRx includes a complete **Model Context Protocol (MCP)** server engine (`LipiRxMcpServer`) compliant with standard JSON-RPC 2.0 specifications.

```
  ┌─────────────────────────────────────────────────────────────┐
  │  External MCP Clients (Claude Desktop, Cursor, POS Software)│
  └──────────────────────────────┬──────────────────────────────┘
                                 │ HTTP POST (http://localhost:8080/lipirx/mcp)
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                   McpHttpServer (Port 8080)                 │
  └──────────────────────────────┬──────────────────────────────┘
                                 │ JSON-RPC 2.0 Payload
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                    LipiRxMcpServer Engine                   │
  └──────────────┬───────────────────────────────┬──────────────┘
                 │                               │
                 ▼                               ▼
     ┌───────────────────────┐       ┌───────────────────────┐
     │     MCP Resources     │       │       MCP Tools       │
     │  (Room 3 KMP History, │       │    (RxAgentTools      │
     │   Config & Traces)    │       │   OCR/Parsing/Traces) │
     └───────────────────────┘       └───────────────────────┘
```

### Exposed Capabilities:
- **MCP Resources (`resources/list`, `resources/read`)**:
    - `lipirx://history/scans`: Accesses Room 3 KMP prescription scan history and extracted items.
    - `lipirx://config/providers`: Queries current AI provider configurations and assigned models.
    - `lipirx://history/traces`: Reads AgentOps SQLite forensic execution traces.
- **MCP Tools (`tools/list`, `tools/call`)**:
    - `scan_prescription_vision_ocr`: Executes vision OCR on base64 image input.
    - `parse_medical_entities`: Normalizes brand names, dosages, forms, and schedules.
    - `search_generic_substitutes`: Cross-references generic compositions and Bangladeshi brand substitutes.
    - `audit_patient_safety`: Audits clinical safety warnings and flags dosage anomalies.
    - `get_agent_execution_traces`: Queries recent agent execution trace records from SQLite.
    - `eval_run_benchmark`: Executes automated multi-agent evaluation suite on-device and returns JSON summary report.
- **Local HTTP Transport (`McpHttpServer`)**: Runs an embedded HTTP server on port `8080` (`http://localhost:8080/lipirx/mcp`) with CORS preflight support so terminal commands (`curl`/PowerShell `Invoke-RestMethod`), Claude Desktop, and local Pharmacy POS desktop software can connect directly.

## 📱 Edge On-Device AI & LiteRT-LM Support

LipiRx includes native **On-Device SLM** execution using Google's **LiteRT-LM** (`litertlm-android`) and LiteRT runtime (`.litertlm` and `.tflite` model files).

### On-Device Execution Strategies
- **Hybrid Fallback** *(Default)*: Cloud AI First (3 attempts) → Automatic On-Device SLM Fallback on network drops, server errors, or API quota limits.
- **On-Device First**: Local NPU First → Cloud AI Escalation (3 attempts) for complex safety auditing.
- **On-Device Only**: Strict 100% Offline / Local Execution Only.
- **Cloud Only**: Disable On-Device SLM → Cloud AI Only (3 attempts).

## 🛠️ Tech Stack & Architecture

- **Platforms**: Android & iOS
- **UI Framework**: Compose Multiplatform with Material 3 (adaptive layouts, high-contrast custom themes & 3-way mode toggle)
- **Multi-Agent Pipeline**: `KoogRxSupervisorEngine` + `RxSupervisorAgent` dispatching to type-safe `RxAgentTools`
- **Navigation**: Jetpack Navigation 3 destination state management (`AppNavKey`, `AppNavigator`) with `rememberSaveable` back-stack state persistence across orientation changes
- **Architecture**: MVVM + Feature-based ViewModels (`HomeViewModel`, `ImagePreviewViewModel`, `AnalysisLoadingViewModel`, `ScanResultsViewModel`, `HistoryViewModel`, `SettingsViewModel`)
- **Session State Management**: Centralized `PrescriptionSessionState` managing active scan sessions, isolating history record inspection (`activeScanMedicines`)
- **Theme Animation System**: Single-driver 60/120 FPS linear color interpolation (`LipiColors.lerp`) in `LipiRxTheme.kt` with spring-animated segmented theme controls
- **Local Database**: Room 3.0.3 (`androidx.room3`) KMP SQLite database with `BundledSQLiteDriver` logging provider keys, per-provider models, agent matrix configurations, theme preferences, offline prescription history, and AgentOps execution traces
- **Networking**: Ktor Client 3.x (`OkHttp` for Android, `Darwin` for iOS) with `kotlinx.serialization`
- **Dependency Injection**: Koin 4.x (`koin-core`, `koin-compose`, `koin-compose-viewmodel`, `koin-android`) with modularized DI sub-modules (`networkModule`, `databaseModule`, `aiAgentModule`, `mcpModule`, `domainModule`, `presentationModule`)
- **Testing Framework**: Native KMP unit test suite in `shared/test/` (`AppNavKeyTest`, `PrescriptionSessionStateTest`, `SemVerTest`, `LipiRxMcpServerTest`) + E2E Python automation test runners (`test_full_app.py`, `test_full_app_ui.py`, `test_mcp.py`)

## 🚀 Getting Started

### 🔑 Setting Up AI Providers & On-Device Strategy
1. Launch **LipiRx** on your Android device.
2. Tap the **Settings** icon on the top header or preview screen.
3. Configure your API keys for your preferred cloud providers (**`🤖 Gemini`**, **`🌐 OpenAI`**, **`🟧 Claude`**, **`⚡ Groq`**, or **`🛠️ Custom URL`**) or select your **On-Device AI & Fallback Strategy**.
4. Customize primary and fallback agent assignments in the **Per-Agent AI Assignments** matrix.

### 🔌 Testing the MCP Server via Terminal (PowerShell / `curl`)
1. Forward the port if testing on emulator or USB device:
   ```bash
   adb forward tcp:8080 tcp:8080
   ```
2. Query registered MCP tools:
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:8080/lipirx/mcp" -Method Post -ContentType "application/json" -Body '{"jsonrpc":"2.0","id":"1","method":"tools/list"}' | ConvertTo-Json -Depth 5
   ```
3. Read SQLite AgentOps forensic execution traces:
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:8080/lipirx/mcp" -Method Post -ContentType "application/json" -Body '{"jsonrpc":"2.0","id":"2","method":"resources/read","params":{"uri":"lipirx://history/traces"}}' | ConvertTo-Json -Depth 5
   ```
4. Query recent agent traces using the `get_agent_execution_traces` tool:
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:8080/lipirx/mcp" -Method Post -ContentType "application/json" -Body '{"jsonrpc":"2.0","id":"3","method":"tools/call","params":{"name":"get_agent_execution_traces","arguments":{"limit":"10"}}}' | ConvertTo-Json -Depth 5
   ```
5. Trigger on-device multi-agent evaluations using the `eval_run_benchmark` tool:
   ```powershell
   Invoke-RestMethod -Uri "http://localhost:8080/lipirx/mcp" -Method Post -ContentType "application/json" -Body '{"jsonrpc":"2.0","id":"4","method":"tools/call","params":{"name":"eval_run_benchmark","arguments":{}}}' | ConvertTo-Json -Depth 5
   ```

### 📱 Installing Local SLM Weights (Optional for Offline Mode)
To run local models offline:
1. Download a `.litertlm` model file (e.g., `Qwen3-0.6B.litertlm` from Hugging Face `litert-community`).
2. Push the file to your device storage via `adb`:
   ```bash
   adb push Qwen3-0.6B.litertlm /sdcard/Android/data/com/snehonir/lipirx/files/model.litertlm
   ```

#### 📦 Generating Custom-Named Android Debug & Release APKs

You can generate custom-named APKs directly into a dedicated `apks/` directory using the provided build helpers:

- **Generate Custom-Named Debug APK (`apks/LipiRx-v0.5.2-debug.apk`)**:

  ```powershell
  # Windows PowerShell

  ./build-apk.sh debug
  ```

- **Generate Custom-Named Release APK (`apks/LipiRx-v0.5.2-release.apk`)**:
  ```powershell
  # Windows PowerShell
  .\build-apk.bat release

  # macOS / Linux
  ./build-apk.sh release
  ```

- **Generate Signed Release APK (`apks/LipiRx-v0.5.2-release-signed.apk`)**:
  ```powershell
  # Windows PowerShell
  .\sign-release.bat

  # macOS / Linux
  ./sign-release.sh
  ```

- **Standard Build Task Commands**:
    - Debug APK: `.\kotlin.bat task :androidApp:buildAndroidDebug`
    - Release APK (R8 Minified): `.\kotlin.bat task :androidApp:buildAndroidRelease`

- **Optimizing APK Size for Physical Devices**:
  To shrink the APK size from ~90 MB down to **~35–45 MB**, target only 64-bit ARM architecture (`arm64-v8a`) in `androidApp/module.yaml`:
  ```yaml
  settings:
    android:
      abiFilters:
        - arm64-v8a
  ```

- **Build shared module**:
  ```bash
  ./kotlin task :shared:compileAndroidDebug
  ```

- **Run Android App**:
  ```bash
  ./kotlin run -m androidApp
  ```

  ```bash
  ./kotlin run -m iosApp
  ```
